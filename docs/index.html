Hello, contractor workflow.

A minimal static project that demonstrates how Codex plans work, dispatches bounded tasks to outside model contractors through Beads, and integrates their output into a published result.

Workflow

Every change follows a four-step lifecycle managed by Codex as the principal architect and integrator.

  1. 1

    Codex creates the baseline project

    Architecture, static app, validation script, CI, and repo instructions are committed to main.

  2. 2

    Antigravity documents the project on a patch branch

    Google Antigravity receives a contractor packet and writes the project guide on agy/docs.

  3. 3

    Claude Code creates the GitHub Pages experience

    Claude Code receives its own packet and builds the public documentation site on claude/pages.

  4. 4

    Codex validates, reviews, merges, and publishes

    Contractor returns are evaluated against acceptance criteria. Accepted branches merge to main and GitHub Pages goes live.

Architecture

The project is dependency-free: standard HTML and CSS for the app, built-in Python for validation, and GitHub Actions for CI.

Beads

A task-tracking system that models the work graph as a DAG of dependencies. Beads records contractor dispatch, return evidence, and acceptance decisions.

Contractor packets

JSON-formatted prompts containing context, allowed file paths, a job-description label, and acceptance criteria. Each packet scopes exactly one bounded assignment.

Patch branches

Contractors work on dedicated branches (agy/docs, claude/pages) and may only edit their assigned paths. No direct pushes to main.

Validation

python3 scripts/check_site.py runs locally and in CI to verify structural elements, stylesheet links, content requirements, and absence of placeholder markers.

Contractor model

Outside model contractors operate under strict boundaries that guarantee security, quality control, and codebase integrity.

Branch isolation

All contractor work happens on designated patch branches. Contractors never write directly to main.

Path restrictions

Each Bead specifies allowed_paths. Contractors may only create or edit files within that list.

Evaluation gate

Codex evaluates every contractor return against the Bead acceptance criteria before merging. Rejected work triggers a repair cycle.

No secrets or destructive commands

Contractors must not access credentials, rotate secrets, force-push, delete branches, or run destructive operations.

Lifecycle

  1. Codex defines a Bead task with acceptance criteria
  2. Codex compiles and dispatches a handoff packet
  3. Contractor implements changes on the assigned patch branch
  4. Contractor runs local validation and submits a return
  5. Codex evaluates the return against criteria
  6. Accepted branches merge to main; rejected work is repaired

Get started

Clone the repository and run the validation script to verify the baseline. 

git clone https://github.com/gprocunier/hello-world-contractor-demo.git
cd hello-world-contractor-demo
python3 scripts/check_site.py
python3 -m http.server 8000

Then visit http://localhost:8000 to see the baseline app.
